# Cryptographic Provider Boundary

The identity subsystem requires a real Ed25519 implementation.

The current repository bootstrap establishes the identity-key interface,
but the final cryptographic provider MUST be selected and integrated before
System Identity is accepted as production-ready.

Do not treat randomly generated byte arrays as an Ed25519 key pair.

Acceptance requirement:

- Public/private key relationship must be cryptographically valid.
- Signatures must verify.
- Private key material must never be serialized into public identity records.
- Key storage must be protected by the platform security boundary.

This document intentionally prevents a placeholder implementation from
being mistaken for cryptographic correctness.
